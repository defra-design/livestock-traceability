Global search options

We explored different ways to search across animals, holdings and keepers from one place.

Option 1: One search with grouped results

View grouped global search

One search checks animals, holdings and keepers, then shows a small number of results for each type.

  • Why it could work: users can search with whatever information they have without choosing a record type first.
  • Issue: the results page can become long, so each group needs a sensible preview limit.

Global search pattern for option 1

The same search term is checked against all 3 record types at the same time.

  • Results are grouped into Animals, Holdings and Keepers.
  • Each group shows up to 5 results.
  • If there are more than 5 results in a group, the user gets a View all results link to the existing individual search.
  • If a record type has no matches, that section is not shown.
  • The overall result count is the total number of matching animals, holdings and keepers combined.

Animals

The search checks:

  • ear tag number, partial match
  • CPH number, exact match

Animal results show:

  • ear tag
  • CPH
  • holding name
  • status

So, for example, searching a full CPH can return animals recorded against that holding.

Holdings

The search checks:

  • CPH number
  • holding name
  • business name
  • town
  • county
  • postcode
  • herd or flock mark

These use partial matching, so a term such as Low Wood, Cumbria or part of a CPH can return matching holdings.

Keepers

The search checks:

  • name
  • first name
  • last name
  • email address
  • phone number
  • postcode

These also use partial matching.

Option 2: Choose a record type before searching

View scoped search with radios

Users choose Animal, Holding or Keeper, then search only within that area.

  • Why it could work: results are focused and the page only needs to show one result type.
  • Issue: users need to know the record type before searching. A valid search can return nothing if the wrong option is selected.
  • Issue: it starts to duplicate the existing individual animal, holding and keeper searches.

Option 3: Search results in tabs

One search checks all three areas, with separate tabs for Animals, Holdings and Keepers.

  • Why it could work: keeps the page compact and allows each result type to keep its own table design.
  • Issue: there is no obvious All tab because each result type needs different columns.
  • Issue: one tab has to be selected by default, which could hide relevant results in another tab.
  • Issue: responsive tab behaviour could make large result sets cumbersome on smaller screens.

Option 4: Mixed result cards

Show animals, holdings and keepers together using a flexible card layout rather than separate tables.

  • Why it could work: cards can show different information for each record type and adapt well to different screen sizes.
  • Issue: record types would need to be clearly distinguished.
  • Issue: mixed cards introduce a difficult ordering question about which result type should appear first.
  • Issue: cards use more vertical space and may be slower to scan than compact tables.
Current direction: continue with the grouped global search while keeping the other options documented as alternatives explored.
